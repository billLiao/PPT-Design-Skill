# 设计决策手册 · Design Playbook

> 本手册解决一个问题：**拿到内容后，如何做设计决策**。
> 版式坐标在 [design-system.md](../design-system.md)，那里是"基线"；这里告诉你**什么时候偏离基线、怎么偏离**。
> 坐标是起点，不是牢房——照抄坐标而不适配内容，是生成质量差的第一原因。

---

## 0. 核心理念：先规划，后编码

**禁止拿到主题就直接写 pptxgenjs 代码。** 结构错了，后期翻修代价是重写。

正确顺序：

```
内容分析 → 叙事弧 → 页面规划表 → 逐页生成 → QA
```

用户给了完整大纲时可以压缩前两步，但**页面规划表永远不能跳过**（哪怕只在心里过一遍，也要确认每页的内容形状和版式匹配）。

---

## 1. 叙事弧（Narrative Arc）

按场景选一条骨架，把内容填进去。没有大纲时，用叙事弧帮用户搭。

### 场景 A · 产品/技术发布

```
钩子 Hook      → 1 页   : 反差数据 /尖锐问题，让人停下来
定调 Context   → 1-2 页 : 背景 / 你是谁 / 为什么现在讲这个
方案 Core      → 3-5 页 : 核心能力，每页只讲一个点
证据 Proof     → 2-3 页 : 数据 / 案例 / 对比
收束 Action    → 1 页   : 行动号召 / 路线图
```

### 场景 B · 行业分享/观察

```
钩子 Hook      → 1 页   : 反直觉结论开场
定调 Context   → 1 页   : 我是谁 / 观察视角
现象 Phenomenon → 2-3 页 : 发生了什么（数据 + 案例）
分析 Analysis  → 3-4 页 : 为什么（归因 / 机制 / 框架）
转折 Shift     → 1 页   : 打破预期的新观点
收束 Takeaway  → 1-2 页 : 金句 / 悬念问题
```

### 场景 C · 工作汇报/复盘

```
结论先行       → 1 页   : 一句话结论 + 3 个支撑点
背景           → 1 页   : 目标与基线
进展 Progress  → 2-3 页 : 关键数据（图表页）
问题 Problem   → 1-2 页 : 差距与归因
方案 Plan      → 1-2 页 : 下一步（时间线）
```

**规则**：每一页都必须能回答"这一页在叙事里的任务是什么"。答不上来的页删掉。

### 观众状态转移（AST · 每页的验收标准）

> PPT 不只是信息容器，而是观众状态改变器。（思路来自 humanize-ppt 的 AST 理论）

叙事弧只保证"顺序对"，AST 保证"每页有效"。规划每一页时回答三个问题：

- **Audience**：观众是谁？已经知道什么？抗拒什么？
- **State**：翻到这页之前观众处于什么状态？看完这页该变成什么状态？
- **Transfer**：这页靠什么推动这个转移？（一个数据 / 一个案例 / 一个反差 / 一个演示）

**失败页的定义**：观众看完这页，状态没有任何变化——只有几个字没把意思说完、或堆了信息但没推动理解。这种页删掉或合并。

**讲稿测试**：写完一页，试着口头讲这一页。讲不出两句话的页 = 只能看不能讲 = 失败页。

## 2. 页面规划表（强制产出）

写代码前，先产出这张表（可直接给用户确认，也可作为内部草稿）：

```markdown
| 页码 | 角色     | 版式        | 明暗 | 观众状态 A→B          | 内容形状              | 视觉元素       |
|------|----------|-------------|------|------------------------|-----------------------|----------------|
| 1    | 钩子     | cover       | 深   | 无兴趣→想听下去        | 标题 8 字 + 副题 15 字 | 大字 + kicker  |
| 2    | 定调     | two-column  | 浅   | 想听→知道讲什么        | 3 段 × 40 字          | 右侧图片       |
| 3    | 方案 1   | big-number  | 浅   | 知道→相信可行          | 4 项 × 8 字 + 20 字   | 数字卡片       |
| 4    | 证据     | chart       | 浅   | 相信→被说服            | 6 个月趋势            | 原生折线图     |
| 5    | 转折     | quote       | 深   | 被说服→产生新疑问      | 金句 20 字            | 大字引用       |
| 6    | 收束     | section     | 深   | 疑问→知道下一步        | 行动号召 12 字        | —              |
```

**内容形状**必须具体到"几项 × 几个字"——这是选版式和做自适应的依据。
**观众状态 A→B** 是每页的验收标准：状态没变化的页删掉（见上文 AST 一节）。

### 明暗节奏规则（Theme Rhythm）

- 封面 / 章节幕封 / 大引用 / 收束 = **深底 hero 页**；正文 = 浅底
- **连续 3 页同明暗 = 视觉疲劳**，必须插入对比页
- 每 3-4 页插入 1 个 hero 页（章节/大数字/引用）
- 8 页以上的 deck 必须有 ≥1 个深底正文页（数据大字报最适合深底）
- 一份 deck 只用一套主题，只切换明暗变体，**永不换主题**

### 行动标题（Action Titles）

标题写**结论或判断**，不写话题标签。观众扫一遍标题就能听懂整个故事线（skim test）——做不到就说明标题还是话题式。

| 话题式 ❌ | 行动式 ✅ |
|-----------|----------|
| 背景介绍 | 老系统已把月结对账拖到 3 天 |
| 数据情况 | 人工对账每月烧掉 40 工时 |
| 方案说明 | AI 预审把对账压回 2 小时 |
| 实施计划 | 先在财务部跑 30 天，再推全公司 |
| 总结 | 三个月回收成本，下一步扩到采购部 |

- 优先「数字 + 判断」结构；长度中文 ≤ 12 字（封面 ≤ 8 字）
- 例外：封面 / 章节幕封 / 大引用页可以是话题式或情绪式，不强制结论
- outline.json 的 `title` 字段按此规则填写；`outline_check.py` 对话题式标签词给警告

## 3. 内容形状 → 版式决策树

先看内容长什么样，再选版式。**数据专用版式必须有真实数据**，不能拿文案硬填。

```
内容是什么？
├─ 一个大数字 / 一个核心指标
│   ├─ 单数字 + 一句话 → big-number（单卡变体）
│   └─ 3-6 个并列指标 → big-number（网格变体）
├─ 3-6 个并列概念/特性
│   ├─ 均等重要 → 卡片网格（big-number / S04 / S19）
│   └─ 有一项要突出 → 网格 + 单张 accent 卡（只突出一张）
├─ 流程 / 步骤（3-7 步）→ pipeline / S11
├─ 时间演化（3-7 个节点）→ S02 / S11 时间线
├─ 对比（旧 vs 新 / A vs B）→ before-after / S08
├─ 排名 / 比较（5-10 项）→ 原生条形图（addChart BAR, barDir:"bar"）
├─ 趋势（时间序列）→ 原生折线图（addChart LINE）
├─ 构成 / 占比（3-5 部分）→ 原生环形图（DOUGHNUT）或条形图
├─ 多维综合对比（3-6 维 × 2-3 对象）→ 原生雷达图（RADAR）
├─ 转化漏斗（4-6 级递减）→ 漏斗：宽度递减的居中矩形（形状拼，pptxgenjs 无原生漏斗）
├─ 项目排期（任务 × 时间）→ 甘特：行 + 按时间比例的横条（形状拼）
├─ 增减拆解（期初→期末）→ 瀑布：浮动柱（形状拼，或堆叠柱透明底技巧）
├─ 引用 / 金句 → quote / S09
├─ 三层架构 / 系统 → S05 / S17
├─ SWOT / PEST / 商业模式画布 / 双钻 / 竞争定位 → templates/layouts/analysis-models.md
├─ 单张图片 → two-column（左文右图）
├─ 2-6 张图片 → image-grid / S15 / S16
└─ 大图 + 数据 → S22
```

**图表实现优先级**：原生 addChart（bar/line/pie/doughnut/radar/scatter）> 形状拼（漏斗/甘特/瀑布）> 贴图（最后手段）。形状拼的图表数据标签用 addText，位置按数值比例算好。

**版式多样性**（硬规则）：
- 7-8 页 deck：≥ 5 种不同版式
- 10 页以上：≥ 7 种不同版式
- 不允许连续 3 页同一版式结构
- 图表页算独立版式类型

## 4. 版式自适应规则（核心章节）

design-system.md 的坐标是**4 项内容、标准文字长度**下的基线。实际内容几乎总是不同，按以下规则变形。

### 4.1 横向卡片行：N 项的通用公式

基线是 4 卡（每卡 w=2.1，间距 0.3，从 x=0.5 起）。N 项时：

```javascript
const N = items.length;
const gap = 0.3;
const w = (9 - (N - 1) * gap) / N;   // 9" 可用宽度
const x0 = 0.5;
// 第 i 张卡: x = x0 + i * (w + gap)
```

| N | 卡宽 w | 字号调整 |
|---|--------|----------|
| 2 | 4.35   | 标题 +4pt，正文 +2pt |
| 3 | 2.8    | 基线字号 |
| 4 | 2.1    | 基线字号（基线即 4 项） |
| 5 | 1.62   | 标题 -4pt，正文 -2pt，说明删到 ≤15 字 |
| 6 | 1.25   | 改用 3×2 网格（w=2.8, 两行），不要硬排一行 |

**超过 6 项**：不许再缩。拆两页，或改成表格行（rowline），或只保留 Top 5 + "其他"。

### 4.2 条目增减的字号阶梯

内容比基线少 → 放大一档，同时**把版面重心下移**（y 居中），不要让上半页挤、下半页空：

```javascript
// 3 项内容占 4 项的版面时：垂直居中修正
const contentH = 2.8;                    // 实际内容高度
const yStart = 0.9 + (3.8 - contentH) / 2; // 3.8 = 基线内容区高度
```

内容比基线多 → 按"删文案 → 拆页 → 换版式 → 降字号"顺序处理，**降字号是最后手段**（正文不得低于 14pt）。

### 4.3 文字长度规则（中文）

| 元素 | 舒适长度 | 超长处理 |
|------|----------|----------|
| 封面主标题 | ≤ 8 字 | 9-12 字降一档字号；>12 字必须拆两行或重写 |
| 页面标题 | ≤ 12 字 | >16 字重写——标题不是句子 |
| 卡片标题 | ≤ 8 字 | 超了换更短的词，不要缩文本框 |
| 卡片说明 | ≤ 30 字 | 超了删到 30 字内，删不掉拆页 |
| 列表条目 | ≤ 18 字 | 超了拆成两条 |
| 引用金句 | ≤ 24 字 | 超了就不是金句，重写 |

**禁止**：为了塞进长文字而缩小字号、缩窄文本框、压缩行距。先改文案，再动版式。

### 4.4 每个版式的弹性区间

| 版式 | 弹性维度 | 区间 |
|------|----------|------|
| cover | 主标题字号 | 40-60pt（≤8 字用上限） |
| cover | 标题行数 | 1-2 行（2 行时行距 1.1，y 上移 0.2） |
| section | 标题字号 | 36-48pt |
| big-number | 网格 | 1×1 / 2×2 / 3×2 / 4×2（数字 54-72pt） |
| two-column | 图文占比 | 4:5 ~ 5.5:3.5（文字多左宽，图多右宽） |
| pipeline | 步骤数 | 3-7 步（>5 步箭头改细线连接） |
| quote | 引文字号 | 28-40pt（≤16 字用上限） |
| chart | 图表尺寸 | ≥ 6×3.5，数据标签 10-12pt |

### 4.5 变形后必须自检

每次偏离基线，生成后重点检查该页：
- 文字是否溢出卡片/文本框（中文方块字宽 = 字号 × 1.0，英文 ≈ × 0.55，可预算）
- 卡片间距是否仍均匀（变形后重新算 x，不要手估）
- 垂直方向是否居中或贴齐网格线

## 5. 中文排版规则

### 5.1 字号分档（中文方块字视觉面积大，不能套英文标准）

| 元素 | 中文 deck | 英文 deck |
|------|-----------|-----------|
| 封面主标题 | 44-60pt | 48-66pt |
| 章节标题 | 36-44pt | 40-48pt |
| 页面标题 | 26-34pt | 28-36pt |
| 卡片标题 | 16-20pt | 18-22pt |
| 正文 | 14-16pt | 14-16pt |
| 说明/caption | 10-12pt | 10-12pt |
| 数据大字 | 54-80pt | 60-88pt |

### 5.2 硬规则

- **最小字号**：投屏场景正文 ≥ 14pt，caption ≥ 10pt；放不下先删文案
- **字重**：标题 bold，正文 regular；**禁止整页全 bold**（没有对比就没有层级）
- **行距**：正文 `lineSpacingMultiple: 1.3-1.5`；标题 1.1
- **中西混排**：数字和英文标签用 mono（Consolas）或 Arial，中文用雅黑/宋体系——数字用中文字体会显得糊
- **标点**：中文 deck 用全角标点；引用用「」不用 ""

### 5.3 字体策略（Office 安全字体）

**写进 pptx 的字体由用户的 PowerPoint 渲染**。网页字体（Inter / Playfair / Noto 系列）用户机器上没有，会 fallback 到宋体，杂志感直接垮掉。只用下表字体：

| 风格 | 角色 | 中文 deck | 英文 deck |
|------|------|-----------|-----------|
| 杂志风 | 标题（衬线） | 华文中宋 STZhongsong | Cambria / Bookman Old Style |
| 杂志风 | 正文 | 微软雅黑 Microsoft YaHei | Calibri |
| 杂志风 | 数字/标签（mono） | Consolas | Consolas |
| 瑞士风 | 标题（无衬线粗） | 微软雅黑 Microsoft YaHei（bold） | Arial（bold） |
| 瑞士风 | 正文 | 微软雅黑 Microsoft YaHei | Arial |
| 瑞士风 | 数字/标签（mono） | Consolas | Consolas |

- 用户明确指定字体时照做，但该文本框字号预留 ~10% 余量（QA 渲染宽度不可信）
- Mac 用户：微软雅黑缺失时系统会 fallback 苹方，可接受；不要主动写 PingFang（Windows 没有）

## 6. 信息密度控制

**一页一个论点。** 密度超标的页面不是"信息丰富"，是没有完成提炼。

| 指标 | 上限 | 超标处理 |
|------|------|----------|
| 每页正文字数（中文） | 90 字 | 拆页 |
| 列表条目数 | 5 条 | 拆页或改表格 |
| 单条长度 | 18 字 | 拆条 |
| 卡片数 | 6 张 | 拆页或改 3×2 网格 |
| 图表数 | 1 个/页 | 拆页 |
| 图表数据点 | 折线 ≤ 12 个，条形 ≤ 10 根，饼 ≤ 5 块 | 合并类目 |

**提炼技巧**：写完一页，把正文删掉 30% 再读一遍——如果意思没损失，说明原来就是废话。

## 7. 视觉母题（Motif）

选 **一个** 可重复的视觉元素，贯穿全 deck：

- 数字卡片（tint 底 + accent 大数字）
- mono 标签系统（kicker / 页码 / 数据标签统一用 Consolas + accent 色）
- 圆形图标底（icon 在 accent 色圆内）
- 巨型背景字（Ghost number，章节页用超大 tint 色数字压底）

**禁止**的母题：accent 色条 / 标题下划线 / 渐变 / 阴影堆叠——这些是 AI 味的标志。

### CRAP 四原则（每页过一遍）

来自 Robin Williams《写给大家看的设计书》，ppt-master 同款方法论：

- **Contrast 对比**：字号/字重/颜色/明暗要有明显层级——对比不够等于没有层级
- **Repetition 重复**：母题、间距、字号档位全 deck 重复——重复产生专业感
- **Alignment 对齐**：一切元素对齐到网格或另一元素的边缘——禁止"差不多对齐"
- **Proximity 亲密**：相关内容靠近成组，组间留大空隙——观众靠距离理解分组

### 封面-结尾呼应

收束页复用封面的构图/配色/母题（如封面的大编号 + 右标题 → 结尾镜像），形成闭环。观众会在潜意识里感到"讲完了"。

## 8. 规划层自检（写代码前过一遍）

- [ ] 每一页都能说出叙事任务，且观众状态 A→B 明确（状态不变的页已删）
- [ ] 每一页口头能讲出两句话以上（讲稿测试）
- [ ] 页面规划表已产出，内容形状具体到"几项 × 几字"
- [ ] 明暗节奏：无连续 3 页同明暗，每 3-4 页有 hero，结尾呼应封面
- [ ] 版式多样性达标（7 页 ≥ 5 种），分析模型页 ≤ 2 页
- [ ] 数据页都有真实数据，没有文案硬填
- [ ] 每页正文 ≤ 90 字
- [ ] 中文标题都 ≤ 12 字（封面 ≤ 8 字）
- [ ] 字体全部来自安全字体表
- [ ] CRAP 四原则逐条想过（对比/重复/对齐/亲密）
